# PROJECT_SPEC.md: CCPA Dark Pattern Auto-Auditor

Source of truth for what is being built. Owner-maintained. Agents must not edit this file.

## 1. Purpose

An evidence-driven audit system that visits consumer-facing websites, records what a user would see at each step, and flags **potential** dark patterns against the 13 categories named in the Guidelines for Prevention and Regulation of Dark Patterns, 2023 (Central Consumer Protection Authority, India).

It is **not** an AI that declares sites legally non-compliant. It produces reproducible evidence and reviewable hypotheses; qualified humans make every legal determination.

## 2. Goals

1. Run a bounded browser audit against a public URL and capture ordered steps.
2. Preserve per-step evidence (screenshot, DOM snapshot) with timestamps and SHA-256 hashes.
3. Analyse each step with a multimodal model and emit structured, evidence-grounded findings.
4. Map each finding to a taxonomy category and a legal reference.
5. Provide a dashboard where a human reviewer confirms, rejects, or marks findings inconclusive.

## 3. Non-goals

- Automatic legal conclusions or penalties.
- Completing purchases, entering payment details, submitting OTPs, or bypassing logins, paywalls or CAPTCHAs.
- Auditing private, internal or access-controlled targets.
- Public exposure of evidence artifacts.

## 4. Architecture

| Layer | Choice | Notes |
| --- | --- | --- |
| API | FastAPI (Python) | Backend-only secrets |
| Queue | Celery + Redis | Audit runs execute as background jobs |
| Database | Supabase PostgreSQL | Schema in `database/migrations/001_initial_schema.sql` |
| Evidence storage | Private bucket (Supabase Storage default, S3 optional) | Paths stored in DB, never public URLs |
| Browser agent | TinyFish web agent | Integrate against the documented API only; do not assume methods |
| Vision analysis | Google Gemini | Model id from `GEMINI_MODEL`, never hard-coded |
| Frontend | Next.js (TypeScript) | Public config only; talks to FastAPI |
| Realtime | WebSocket | Authenticated, origin-restricted (later phase) |

## 5. Data model (Phase 1)

- `platforms`: registered websites (unique `domain`).
- `audit_sessions`: one row per audit run; carries status, trigger source, provenance (agent, model, taxonomy version).
- `audit_steps`: ordered browser states per session; private object paths plus SHA-256 hashes.
- `dark_pattern_violations`: machine-generated findings; default `PENDING_REVIEW`; JSONB `evidence` array; review fields.

RLS is enabled on all four tables with **no** client-facing policies. Backend access uses server-side credentials only.

## 6. Taxonomy: the 13 categories

Enum `ccpa_dark_pattern_category`:

| Enum value | Category |
| --- | --- |
| `FALSE_URGENCY` | False Urgency |
| `BASKET_SNEAKING` | Basket Sneaking |
| `CONFIRM_SHAMING` | Confirm Shaming |
| `FORCED_ACTION` | Forced Action |
| `SUBSCRIPTION_TRAP` | Subscription Trap |
| `INTERFACE_INTERFERENCE` | Interface Interference |
| `BAIT_AND_SWITCH` | Bait and Switch |
| `DRIP_PRICING` | Drip Pricing |
| `DISGUISED_ADVERTISEMENT` | Disguised Advertisement |
| `NAGGING` | Nagging |
| `TRICK_QUESTION` | Trick Question |
| `SAAS_BILLING` | SaaS Billing |
| `ROGUE_MALWARE` | Rogue Malware |

"Lack of Transparency" is not a substitute for any of these. A category match marks a *potential* pattern, not an automatic violation. Legal reference text for each category must be taken from the official guideline text supplied by the owner, not generated by the agent.

## 7. Safety and security requirements

- Validate every submitted URL; restrict to publicly reachable hosts (block private, loopback, link-local and metadata addresses).
- `AUDIT_ALLOW_PURCHASES=false`; the agent never submits orders, payments or OTPs.
- Enforce `AUDIT_MAX_STEPS`, `AUDIT_TIMEOUT_SECONDS`, `AUDIT_MAX_CONCURRENT_RUNS`, `AUDIT_MAX_DOM_BYTES`.
- Evidence retention is configurable (`AUDIT_EVIDENCE_RETENTION_DAYS`); the default is a starting policy, not a statutory requirement.
- Screenshots and DOM captures may contain personal or session data: private storage only, no public URLs.
- Secrets: backend `.env` only; frontend may hold `NEXT_PUBLIC_*` public values only. `SUPABASE_SERVICE_ROLE_KEY` is never public.

## 8. Configuration contract

Defined by `backend/.env.example` and `frontend/.env.example`. Variable names are fixed. `GEMINI_MODEL` and `TINYFISH_API_BASE_URL` stay empty until the owner confirms supported values from current vendor documentation.
